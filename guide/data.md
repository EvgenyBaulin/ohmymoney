# Ваши данные

Всё хранится в контейнере песочницы приложения:

```text
~/Library/Containers/io.github.EvgenyBaulin.ohmymoney/Data/Library/Application Support/OhMyMoney/Release/
  finance.sqlite     база данных (пока приложение работает, рядом с ней лежат -wal и -shm)
  backups/           автоматические копии базы; рядом с копией дня и копией «перед обновлением» — папка с читаемой версией (CSV)
  models/            модель категорий; если её нет, она заново обучается на ваших данных
  Logs/              журнал приложения: 5 файлов по 2 МБ, по кругу
```

## Бэкапы

- Копия делается **после каждого изменения**, через несколько секунд, так что серия правок даёт
  одну копию. Она снимается через backup API SQLite, проходит быструю проверку
  (`PRAGMA quick_check`) и только потом получает своё имя; недописанная копия никогда не
  выглядит как исправная.
- В имени — дата, версия и причина: `2026-10-06 23.32 · 1.12.0 · после правки.sqlite`. Дата и
  время стоят первыми, поэтому Finder сортирует копии по времени. Причины: «после правки»,
  «ежедневная», «перед обновлением до N», «перед восстановлением», «перед импортом»,
  «перед исправлением»; слова — на языке интерфейса в момент, когда копия сделана. Копии прежних
  версий (`finance-2026-09-24T101500+0300.sqlite`, `-before-restore`, `-before-import`,
  `-before-migration`) не переименовываются и читаются как раньше. Рядом с каждой новой копией
  лежит маленький файл `….json`: когда сделана, сколько в ней операций, последняя операция,
  остатки по счетам — по нему «Настройки → Бэкапы» показывает список, не открывая копий.
- **Копия дня** — отдельная копия раз в сутки: при первом запуске за день или в 03:00, если
  приложение открыто. Она проверяется полностью (`PRAGMA integrity_check`). Пропущенный день не
  наверстывается.
- **Читаемая версия.** Рядом с копией дня и копией «перед обновлением» лежит папка с тем же
  именем (без `.sqlite`): CSV-файлы в том же формате, что у «Файл → Экспорт», и `README.txt` на
  двух языках. Папка нужна, чтобы посмотреть данные глазами или разобрать их своими скриптами
  (`pandas.read_csv` читает любой файл без параметров); восстановить из неё приложение не
  умеет. У копии «перед обновлением» схема старше нынешней, и в её папке нет таблиц и столбцов,
  которых в той копии ещё не было. Описание самого файла базы — в [database.md](database.md).
- **Прореживание.** Сегодня хранится каждая копия; последняя неделя — по одной в день; год — по
  одной в неделю; старше — по одной в месяц. Из копий дня остаётся последняя. Копия не
  удаляется, пока не проверена более новая, и копия, не прошедшая проверку, не удаляется
  вообще. Копии «перед обновлением» не удаляются сами никогда: в списке виден их общий размер и
  кнопка «Удалить старше года» — с подтверждением и перечнем; самая свежая остаётся.
- **Мало места.** Когда на диске с копиями свободно меньше 1 ГБ, «Настройки → Бэкапы» и «Стоит
  посмотреть» предупреждают об этом; само ничего не удаляется. «Освободить место…» показывает,
  что будет удалено (сначала самые старые копии «после правки», затем ежедневные старше
  года), и удаляет ровно показанное — только после «Да». Копии «перед обновлением» и «перед
  восстановлением» кнопка не трогает.
- **Проверка базы** — раз в неделю сама, тихо, и по кнопке «Проверить сейчас». Она читает, не
  записывая: целостность SQLite, внешние ключи, и правила приложения (части дают сумму
  операции, у сверки есть остатки, перевод идёт между счетами). О проблеме скажет строка в «Стоит
  посмотреть». «Исправить…» сначала делает копию «перед исправлением», потом одним действием
  удаляет только записи-сироты, в которых нет ничего вашего; остальное остаётся и уходит в отчёт.
- **Настройки → Бэкапы → Выбрать папку…** добавляет папку для копий; хорошее место для неё —
  iCloud Drive. Рабочая база никогда не попадает в iCloud — только копии, и в папку уходят лишь
  файлы `.sqlite` копии дня и копии «перед обновлением» (последняя — в подпапку
  `before-migration/`); читаемая версия лежит только на этом Mac. Файлы в iCloud Drive лежат
  открыто, без шифрования.
- **Настройки → Бэкапы → Восстановить…** восстанавливает данные из любой копии. Сначала
  копируется текущее состояние, затем выбранный файл проверяется, и приложение перезапускается
  уже на нём.
- **Сравнить с текущей** у каждой копии и **Сравнить с архивом…** показывают, чем копия или
  архив переноса отличается от базы сейчас: число операций, остатки по счетам, категории,
  добавленные и пропавшие операции; изменённые (по идентификатору) свёрнуты в строку «изменено
  N». Архив с паролем сначала спросит пароль. Ни в базу, ни в копию ничего не пишется.
- Вручную, если приложение не открывается: закройте его, положите копию на место под именем
  `finance.sqlite` и удалите лежащие рядом `finance.sqlite-wal` и `finance.sqlite-shm`.

## Экспорт в CSV

**Файл → Экспорт** (или кнопка «Экспорт» главного окна) записывает 45 CSV-файлов в выбранную
вами папку: операции, их части, возвраты денег, люди, счета, места, события, категории,
шаблоны, плановые платежи, цены подписок, ожидаемые поступления, лимиты, цели, долги, записи
долгов, сверки, курсы, группы счетов, переводы, остатки счетов в сверках, карты, правила
кэшбэка, банки, имущество и его оценки, суммы сроков и расходы кредитов, правила распределения
дохода, свои валюты и настройки, теги, правила, заметки дней, исключения лимитов на месяц, статьи и шаблоны событий, добавки подписок и список прикреплённых файлов (сами файлы в CSV не входят). UTF-8 со строкой
заголовка, суммы — десятичные строки с точкой, даты — в ISO 8601. Сначала приложение
предупреждает: в файлах есть имена и суммы.

Каждый файл открывается `pandas.read_csv(path)` без параметров. Одна оговорка: pandas читает
слова вроде `N/A`, `NA`, `None` или `null` как пропущенные значения, поэтому место или карта,
которые буквально называются «N/A», прочитаются как пустые. Чтобы сохранить такие имена:

```python
pandas.read_csv(path, keep_default_na=False, na_values=[""])
```

## Переезд на другой Mac

1. **Файл → Выгрузить архив…** записывает один файл `OhMyMoney-<date>.ohmymoneyarchive`. Пароль
   необязателен; без него всё внутри можно прочитать, и приложение об этом предупреждает. Сразу
   после записи архив открывается и проверяется ещё раз.
2. Перенесите его по AirDrop, на флешке или через любое облако.
3. На новом Mac установите OhMyMoney, откройте его один раз, затем выберите **Файл → Загрузить
   архив…** — или дважды щёлкните файл. Текущие данные сохраняются в копию, затем заменяются;
   приложение перезапускается.
4. Снова выберите папку для копий: закладки папок никогда не переносятся вместе с архивом.

После этого проверьте: число операций, итоги этого месяца в «Обзоре», людей, места, события,
счета, карты и их правила кэшбэка, остатки, язык, оформление, порядок полей панели ↓, включённые
валюты и валюту по умолчанию. Архив из 1.0.0 или 1.1 загружается в 1.2 и обновляется так же, как
база (см. [«С 1.1 на 1.2»](updates.md#с-11-на-12)); после архива из 1.0.0 снова предлагается «Настройка счетов». Архив из
1.2 версии 1.1 и 1.0.0 не примут.
